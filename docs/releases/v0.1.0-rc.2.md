# ResearchAuditKit v0.1.0-rc.2

## Overview

RC2 is an experimental release candidate for an offline repository-integrity and
evidence-accounting toolkit. This document describes a locally prepared candidate;
RC2 has not yet been tagged or published.

## RC1 to RC2 changes

- Add `prediction-seal` and `prediction-verify` for local consistency records over
  opaque declarations.
- Add `isolation-audit` for declared workspace structure, overlap, path, and
  escaping-symlink checks.
- Add `evidence-index` for deterministic role-labelled evidence inventories.
- Reject duplicate keys and unsafe portable references in the new closed JSON
  contracts.
- Add machine-readable outputs and documented exit semantics for the four commands.
- Add a tested three-minute synthetic demo, command/use-case/limitation/architecture
  documentation, and minimal issue/pull-request templates.
- Include curated public documentation and the synthetic demo in the sdist while
  keeping the wheel runtime-focused.
- Declare hermetic build-test dependencies and retain the Python 3.10-3.12 Ubuntu
  CI matrix.
- Narrow public positioning to mechanical repository checks with explicit
  scientific, publication, and project-decision nonclaims.

The detailed classification is in [RC1 to RC2 Delta](RC1_TO_RC2_DELTA.md).

## Limitations

- Mechanical verification only; supplied policies and metadata can be incomplete.
- No scientific-validity, causal-validity, claim-truth, novelty, or correctness
  judgment.
- No project scoring, publication prediction, acceptance estimate, or continue/stop
  decision.
- No general reproducibility guarantee.
- Local hashes and seals do not establish authorship or an external timestamp.
- Filesystem case, symlink, permission, special-file, and platform behavior can
  affect results; Windows is unverified.
- No external adoption, effectiveness, or performance evidence is claimed.

## Security and privacy

Runtime commands are local/offline and package source does not import network
clients. The toolkit does not execute audited repository code. Portable-reference
checks reject absolute and escaping paths where those closed contracts apply, but
not every user-supplied string is a sanitized publication field. Reports can expose
filenames, paths, sizes, hashes, timestamps, and supplied metadata. Users must
review policies, inputs, output directories, permissions, and reports before
sharing them.

## Artifact integrity

The locally built candidate wheel and sdist are verification artifacts only. Their
SHA-256 values will be reported in the preparation audit, but they are not published
release authority. A formally authorized GitHub prerelease must bind checksums to
artifacts rebuilt from and verified against the exact tag target. No cross-build
byte reproducibility claim is made.

## Upgrade notes

Existing RC1 commands require no documented argument migration. New commands are
opt-in. Consumers that assert the CLI version must update the expected value from
`0.1.0rc1` to `0.1.0rc2`. Consumers adopting the new JSON contracts should account
for their closed-field, duplicate-key, identifier, and portable-reference checks.
