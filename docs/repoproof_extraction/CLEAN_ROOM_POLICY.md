# Clean-Room Policy

## Allowed planning input

Only behavior-level observations from the permitted archive index, closeout/salvage records, generic custody/controller tools, and manifest role/migration descriptions may inform this plan.

## Prohibited transfer

Do not copy, adapt, translate, execute, or test against source-archive code. Do not transfer names, fixture identifiers, predictions, expected outputs, oracles, reviewer material, decisions, agreement/adjudication results, metrics, protocol, schema, evaluator logic, scientific implementation, real data, absolute paths, archive categories, or project-specific branches.

## Implementation controls

- Write new code from this frozen specification and current RAK conventions only.
- Use new generic capability names, schemas, examples, and synthetic fixtures.
- Keep every input local, explicit, lightweight, and deterministic.
- Reject absolute and escaping paths in all new public contracts.
- Do not add network access, GPU use, database storage, background processing, batch orchestration, archive movement, copying, deletion, or rollback execution.
- Preserve all existing command behavior and machine-readable contracts.
- Require review of source similarity and forbidden-term scans before any future merge.

## Verification record

For any later implementation, retain a short design note mapping each new behavior to this plan rather than to a source-archive file. A passing clean-room check confirms only compliance with this policy; it does not establish legal advice or scientific correctness.
